**동작** : 헤더 없는 8비트 그레이스케일 RAW 파일을 `uchar**` 2차원 배열로 읽고, `cv::Mat`으로 옮겨 화면에 띄운다.

## 1. `#include`의 의미

`#include`는 컴파일러가 아니라 **전처리기**가 처리한다. 지정한 헤더 파일의 내용을 그 자리에 그대로 붙여넣는 것이 전부다.

```
소스(.cpp) → 전처리(#include 펼치기) → 컴파일 → 링크(.lib 연결) → 실행 파일
```

헤더에는 함수 **선언**만 있고 실제 구현은 라이브러리(`.lib`, `.dll`)에 있다. <p>
그래서 OpenCV는 `#include`만으로는 부족하고 [00-setup](../00-setup/)에서 한 링커 설정이 있어야 실행 파일이 만들어진다.

| 표기 | 헤더를 찾는 위치 |
|---|---|
| `#include <...>` | 시스템·라이브러리 경로 (VS의 추가 포함 디렉터리 등) |
| `#include "..."` | 현재 소스 폴더를 먼저 찾고, 없으면 시스템 경로 |

## 2. `#include <opencv2/opencv.hpp>`

OpenCV의 주요 모듈 헤더를 한 번에 포함하는 **통합 헤더**다. 편하지만 컴파일이 느려진다. 
이 템플릿에서 실제로 필요한 건 `<opencv2/core.hpp>`와 `<opencv2/highgui.hpp>` 두 개뿐이다.

OpenCV의 클래스와 함수는 `cv` 네임스페이스 안에 있어서 앞에 `cv::`를 붙인다. 
단 `CV_8UC1` 같은 상수는 **매크로**라서 네임스페이스에 속하지 않고, `cv::`를 붙이지 않는다.

이 템플릿에서 OpenCV는 **화면 출력에만** 쓰인다. 파일 입출력과 메모리 관리는 C 표준 라이브러리로 직접 처리한다. 
OpenCV의 `cv::imread`는 헤더 없는 RAW 파일을 읽지 못하기 때문이다.

| 이름 | 종류 | 설명 |
|---|---|---|
| `cv::Mat` | 클래스 | 영상 데이터를 담는 OpenCV 기본 행렬. 생성자는 `Mat(행, 열, 타입)` 순서라 `(height, width, ...)`로 넣는다 |
| `cv::Size` | 구조체 | `width`, `height`를 묶어 표현한다. 이 템플릿에서는 변수 두 개를 담는 용도로만 쓴다 |
| `CV_8UC1` | 매크로 상수 | 8bit Unsigned, Channel 1. 즉 0~255 그레이스케일 |
| `Mat::at<T>(i, j)` | 멤버 함수 | (행 i, 열 j) 원소에 접근한다. `T`는 Mat 타입과 일치해야 한다 (`CV_8UC1` ↔ `uchar`) |
| `cv::namedWindow` | 함수 | 이름과 크기 옵션(`WINDOW_AUTOSIZE`, `WINDOW_NORMAL`)으로 창을 미리 만든다. 이름이 창의 ID 역할을 한다 |
| `cv::imshow` | 함수 | 지정한 이름의 창에 영상을 연결한다. 창이 없으면 자동으로 만들기 때문에, `namedWindow`는 창 옵션을 바꿀 때만 꼭 필요하다 |
| `cv::waitKey` | 함수 | 키 입력을 기다리면서 GUI 이벤트를 처리한다. 인자는 대기 시간(ms)이고 0이면 무한 대기한다. 눌린 키 코드를 반환하고, 시간이 초과되면 -1을 반환한다. 창이 실제로 그려지는 것도 이 이벤트 처리 과정에서다 |
| `cv::destroyAllWindows` | 함수 | 열린 OpenCV 창을 모두 닫고 **창(GUI) 리소스만** 해제한다. 영상 메모리는 해제하지 않는다 |

## 3. `#include <cstdio>` — C 표준 입출력

| 이름 | 설명 |
|---|---|
| `printf` | 콘솔에 서식 문자열을 출력한다 |
| `FILE*` | 열린 파일 **하나**의 스트림 정보(현재 위치, 버퍼 등)를 담은 구조체를 가리키는 포인터 |
| `fopen_s(&f, 이름, 모드)` | 파일을 연다. 성공하면 0을, 실패하면 에러 코드를 반환한다. **MSVC 전용**이라 g++/clang에서는 `fopen`을 써야 한다 |
| `fclose` | 파일을 닫고 버퍼를 비운다 |
| `fread(버퍼, 원소크기, 개수, f)` | 바이너리 데이터를 읽는다. 실제로 읽은 **원소 개수**를 반환하므로 요청 개수와 비교해 에러를 검사한다 |
| `fwrite(버퍼, 원소크기, 개수, f)` | 바이너리 데이터를 쓴다. 반환값 검사 방식은 `fread`와 같다 |
| `getchar` | 콘솔에서 문자 하나를 입력받는다. 템플릿 마지막에서 콘솔 창이 바로 닫히지 않게 대기하는 용도로 쓴다 |

파일 모드의 `b`(`"rb"`, `"wb"`)는 바이너리 모드다. Windows에서 텍스트 모드로 열면 `0x0A`(LF)가 `0x0D 0x0A`(CRLF)로 바뀌어서 픽셀 값이 깨진다. RAW 영상은 반드시 바이너리 모드로 연다.

`<cstdio>`는 `<stdio.h>`의 C++ 버전이다. 기능은 같고 함수를 `std` 네임스페이스에도 넣어준다. C++ 파일에서는 `<cstdio>`를 쓰는 게 관례다.

## 4. `#include <cstdlib>` — C 표준 유틸리티

| 이름 | 설명 |
|---|---|
| `malloc(바이트)` | 지정한 크기만큼 메모리를 할당한다. **초기화하지 않아서** 쓰레기값이 들어 있다 |
| `calloc(개수, 원소크기)` | `개수 × 원소크기`만큼 할당하고 모든 비트를 0으로 초기화한다 |
| `realloc(ptr, 바이트)` | 기존 블록의 크기를 늘리거나 줄인다. 실패하면 NULL을 반환하고 원래 블록은 그대로 남는다. 그래서 `p = realloc(p, n)`처럼 쓰면 실패 시 원래 주소를 잃어 누수가 생기므로 임시 포인터에 받아야 한다 |
| `free(ptr)` | `malloc`/`calloc`/`realloc`으로 받은 메모리를 해제한다 |
| `atoi(문자열)` | 문자열을 `int`로 변환한다. 변환 실패를 알려주지 않고 `"abc"`도 0을 반환한다. 그래서 템플릿에서 `width <= 0`으로 검사한다. 엄격하게 검사하려면 `strtol`을 쓴다 |
| `atof(문자열)` | 문자열을 **`double`**로 변환한다 (이름과 달리 float가 아니다). 실패 시 0.0을 반환하는 문제는 `atoi`와 같다 |
| `exit(상태값)` | 프로그램을 즉시 종료하고 상태값을 OS에 넘긴다. 0은 정상 종료, 0이 아니면 비정상 종료다 → [막힌 점](#에러인데-exit0으로-종료함) |

## 5. `typedef unsigned char uchar;`

`typedef 기존타입 새이름;`은 기존 타입에 **별명**을 붙인다. 새 타입을 만드는 게 아니어서 `uchar`와 `unsigned char`는 컴파일러 입장에서 완전히 같다.

8bit 그레이스케일 픽셀 하나는 0~255 정수 하나이고, 이를 정확히 담는 타입이 `unsigned char`다.

| 타입 | 크기 | 범위 | 픽셀용으로 쓰면 |
|---|---|---|---|
| `char` | 1 B | -128 ~ 127 (대부분의 컴파일러) | 밝기 200이 -56으로 읽힌다. signed 여부도 컴파일러마다 다르다 |
| `unsigned char` | 1 B | **0 ~ 255** | RAW 파일의 1바이트와 1:1로 대응한다 |
| `int` | 4 B | 약 ±21억 | 메모리를 4배로 쓰고, `fread`로 바이트를 바로 읽어 넣을 수 없다 |

- OpenCV에도 같은 `typedef unsigned char uchar;`가 이미 정의되어 있다. C++에서는 같은 타입에 대한 같은 typedef가 중복되어도 에러가 아니다.
- `uchar`끼리 연산하면 `int`로 승격(integer promotion)되어 계산된다. 하지만 결과를 다시 `uchar`에 넣으면 256으로 나눈 나머지만 남는다(300 → 44). 필터 연산을 `int`/`double`로 계산하고 0~255로 클리핑한 뒤 `uchar`에 넣는 이유다.
- 최신 C++에서는 `using uchar = unsigned char;`나 `<cstdint>`의 `uint8_t`를 쓰기도 한다.

## 막힌 점

### 에러인데 `exit(0)`으로 종료함
- 현상: 파일 열기 실패, 메모리 할당 실패 같은 에러 분기에서 모두 `exit(0)`을 호출한다.
- 원인: `exit`의 인자는 프로세스 **종료 상태(exit status)**이고, 0은 "정상 종료"라는 뜻이다. 에러가 나도 OS와 부모 프로세스(VS 디버거, 배치 스크립트)는 성공으로 인식한다. VS 출력 창에도 `코드 0(0x0)으로 종료되었습니다`로 찍혀서 정상 실행과 구분이 안 된다.
- 해결: 에러 분기에서는 `exit(1)` 또는 `<cstdlib>`의 `exit(EXIT_FAILURE)`를 쓰는 게 맞다. 정상 종료는 `EXIT_SUCCESS`(=0)다. 수업 템플릿이라 원본은 그대로 두고 차이만 기록한다.
- 참고: `exit`는 그 자리에서 프로세스를 끝내기 때문에 **지역 객체의 소멸자가 호출되지 않는다**. 예를 들어 지역 `cv::Mat`의 소멸자가 돌지 않는다. 프로세스 메모리는 OS가 회수하므로 지금은 문제가 없다. 하지만 파일 버퍼 flush나 정리 작업이 필요한 코드에서는 `main`에서 `return`으로 빠져나오는 편이 안전하다.

### 2차원 할당에서 첫 `calloc`은 한 번인데 두 번째는 반복문인 이유
- 의문: `uc_alloc`에서 첫 번째 `calloc`은 반복문 없이 한 번만 호출하고, 두 번째 `calloc`은 `for`문으로 여러 번 호출한다.
- 핵심: 두 `calloc`이 할당하는 대상이 다르다. 첫 번째는 픽셀 공간이 아니라 **행을 가리킬 포인터들의 배열**이다.

  ```
  m ──► [ m[0] ] ──► [ p p p ... p ]   ← 0행 픽셀 size_x개
        [ m[1] ] ──► [ p p p ... p ]   ← 1행
        [  ... ]
        [ m[size_y-1] ] ──► [ p p p ... p ]
        └ 1단계: calloc 1번 ┘  └ 2단계: 행마다 calloc → size_y번 ┘
  ```

  1. `calloc(size_y, sizeof(uchar*))`: 포인터 `size_y`개짜리 배열 **하나**를 만든다. 블록이 하나라서 한 번이면 된다. 이 시점의 `m[i]`는 전부 NULL이고, 픽셀을 저장할 공간은 아직 없다.
  2. `m[i] = calloc(size_x, sizeof(uchar))`: 각 행의 픽셀 `size_x`개를 담을 블록을 **행마다 따로** 만들어 `m[i]`에 연결한다. 행이 `size_y`개이므로 반복문으로 `size_y`번 호출한다.

  즉 반복문은 "열 공간"을 만드는 게 아니라 **행 개수만큼 행 블록을 하나씩** 만드는 것이다. 각 블록의 길이가 열 개수(`size_x`)다.
- 이렇게 하는 이유: `img[i][j]`처럼 2차원 첨자로 접근하기 위해서다. `img[i]`가 i행 블록의 시작 주소이고, 거기에 `[j]`를 붙이면 j번째 픽셀이 된다.
- 단점과 대안: 행 블록들이 메모리상에 흩어져 있어서 영상 전체를 `fread` 한 번으로 읽을 수 없다. 그래서 `read_ucmatrix`도 행 단위로 반복한다. 해제할 때도 행마다 `free`한 뒤 포인터 배열을 `free`해야 한다. 픽셀 전체를 **연속된 블록 하나**로 잡으면 `calloc` 두 번으로 끝나고, `cv::Mat`과 같은 메모리 구조가 된다.

  ```cpp
  uchar** uc_alloc_contiguous(int size_x, int size_y)
  {
      uchar** m = (uchar**)calloc(size_y, sizeof(uchar*));       // 행 포인터 배열
      uchar* data = (uchar*)calloc(size_x * size_y, sizeof(uchar)); // 픽셀 전체를 한 블록으로
      if (m == NULL || data == NULL) { free(m); free(data); exit(EXIT_FAILURE); }

      for (int i = 0; i < size_y; i++)
          m[i] = data + i * size_x;   // 할당이 아니라 주소 계산만 반복
      return m;                       // 해제: free(m[0]); free(m);
  }
  ```
